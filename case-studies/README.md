# Case studies

Business analysis work, written as case studies rather than code.

| Case study | Type | What it shows |
|---|---|---|
| [Loan Processing Automation](./loan-processing-automation) | Retrospective case study, with Jira backlog | Stakeholder analysis, as-is and to-be process maps, requirements, user stories with Given/When/Then acceptance criteria, edge cases, assumptions and traceability |
| [Technical Case Study: ACME Home Repairs (Zoho)](./technical-case-study-acme-zoho) | Solution design for a fictional client | Pain points mapped to modules, data flow, risks with fallbacks, discovery questions, kickoff email |

The loan processing case study describes a real production system and was written after
the fact. Its requirements and acceptance criteria were not written before development;
they state the conditions I would use today to judge whether the solution met the need.
Both case studies say what is assumed and what is unmeasured.
